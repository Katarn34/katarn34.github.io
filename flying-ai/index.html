Flying AI.

A 3D flying enemy, in Blueprint only, that dodges obstacles in real time instead of moving step by step. Built as a modular starter AI anyone can reuse, and as the tutorial behind my Unreal Authorized Instructor certification.

Why I built it

Problem
Flying AI in 3D, in Blueprint only, is often avoided or done roughly. Most examples I saw relied on line traces: the AI moved in jerky steps and never looked natural.
Goal
Push it further: an AI that moves continuously, in real time, choosing a safe path around obstacles while it flies, and that stays simple enough to be a starting structure anyone can build behaviour on.
Constraint
It became my tutorial for the Unreal Authorized Instructor certification, with a 30-minute limit. So the system had to go straight to the point and be explainable live.

How it works

Three pieces talk through one Blueprint Interface: the controller decides where it is safe to go, the pawn decides how to fly there.

01A 3D volume from a 2D generatorEQS
The trick

Unreal’s EQS grid generator is flat: it lays points on a plane. A flying AI needs volume. So I wrote a custom EQS context that returns several centres stacked in height, from a first to a last “floor”, with a vertical offset, placed relative to the AI. The grid is generated around each of them, and the flat generator becomes a 3D volume of candidate points.

Scoring

Filter: a sphere trace test removes every point the ship couldn’t reach without hitting something; its radius is tunable to the ship’s size.

Score: a distance test favours points closest to the target, read through the interface by a second custom context.

Result
Re-run on a timer, the query keeps returning the best safe point ahead, so the AI re-plans continuously as the target or the obstacles move.
02Flying like a ship, not a cursorPawn
Movement
The pawn uses Floating Pawn Movement and adds movement input towards the latest safe location, so it moves smoothly instead of teleporting from point to point.
Rotation
Rotation is interpolated towards the direction of travel, with a tunable rotation power and a turning boost for tight turns.
Banking
The ship rolls into its turns: the change in heading drives the roll, clamped between a minimum and a maximum angle and interpolated at a tunable speed. It is a small detail, but it is what makes the flight read as believable.
03Modular by designBlueprint Interface
What I did
The controller, the pawn and the EQS contexts never cast to each other: they communicate through a Blueprint Interface (get target location, set target, set new safe location, set movement state). Any pawn that implements it can use the same controller and query.
Why
The AI is meant as a solid starting structure, not a finished enemy: you plug in your own ship and add behaviour on top. In the tutorial I also show how to move the logic into a Behavior Tree, without making it the focus.

Built for Designers

What I’d do next

Trade-off
The 30-minute tutorial format meant going straight to the point: the logic lives directly in the controller and the pawn.
Next time
Package the movement and banking into an Actor Component, so any pawn gets flight by adding one component, and offer the Behavior Tree version as the default for richer behaviours.
