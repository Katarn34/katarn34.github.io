Flying AI.

Why I built it

Problem
Flying AI in 3D, in Blueprint only, is often avoided or done roughly. Most examples I saw relied on line traces: the AI moved in jerky steps and never looked natural.
Goal
Push it further: an AI that moves continuously, in real time, choosing a safe path around obstacles while it flies, and that stays simple enough to be a starting structure anyone can build behaviour on.
Constraint
It became my tutorial for the Unreal Authorized Instructor certification, with a 30-minute limit. So the system had to go straight to the point and be explainable live.

How it works

Three pieces talk through one Blueprint Interface: the controller decides where it is safe to go, the pawn decides how to fly there.

01A 3D volume from a 2D generatorEQS
The trick

Unreal’s EQS grid generator is flat: it lays points on a plane. A flying AI needs volume. So I wrote a custom EQS context that returns one centre per “floor”: the AI’s location, pushed ahead along its forward vector by a start distance, then raised by floor index × Z offset, from a first to a last floor. The grid is generated around each centre (7,000 units radius, a point every 2,000), and the flat generator becomes a 3D volume of candidate points in front of the ship.

Scoring

Filter: a sphere trace from the AI (1,500 units radius) removes every point it couldn’t reach without hitting something. It only filters, it doesn’t score.

Score 1: distance to the target, closer is better (weight ×1). The target is read through the interface by a second custom context.

Score 2: distance to the AI itself, farther is better (weight ×0.5), so the ship keeps moving forward instead of hovering on the nearest safe point.

Result
The controller runs the query on its Tick, with a delayed tick interval, in Single Best Item mode. When it finishes, the best location is sent to the pawn through the interface (Set New Safe Location). The AI re-plans continuously as the target or the obstacles move.

02Flying like a ship, not a cursorPawn
Movement
The pawn uses Floating Pawn Movement and adds movement input towards the latest safe location, so it moves smoothly instead of teleporting from point to point.
Rotation
The target rotation comes from the velocity: pitch and yaw follow the direction of travel, and RInterpTo blends towards it at a tunable Rotation Power.
Banking
The ship rolls into its turns: the roll is the yaw difference between where the ship faces and where it is going, multiplied by Banking Power and clamped between Min and Max Banking Roll. A sharp turn gives a strong bank, a gentle one barely tilts. It is a small detail, but it is what makes the flight read as believable.

03Modular by designBlueprint Interface
What I did
The controller, the pawn and the EQS contexts never cast to each other: they communicate through a Blueprint Interface (get target location, set target, set new safe location, set movement state). Any pawn that implements it can use the same controller and query.
Movement modes
A Movement State enum (currently Target) shows how new ways of moving can be added side by side, such as patrolling or fleeing, without touching the avoidance logic.
Why
The AI is meant as a solid starting structure, not a finished enemy: you plug in your own ship and add behaviour on top. In the tutorial I also show how to move the logic into a Behavior Tree, without making it the focus.

Built for Designers

Everything that shapes the behaviour is a variable a Designer can change, without opening the graphs.

What I’d do next

Trade-off
The 30-minute tutorial format meant going straight to the point: the logic lives directly in the controller and the pawn.
Next time
Package the movement and banking into an Actor Component, so any pawn gets flight by adding one component, and offer the Behavior Tree version as the default for richer behaviours.
